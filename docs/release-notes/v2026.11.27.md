# v2026.11.27 Release Notes

## What's Changed

- fix(pi): apply system prompt overrides via pi 1.6 forceSystemPrompt; guard normalizeContext against missing messages (3b790232bc)
- fix(zai): resolve thinking=off to the model's declared off effort before session creation (d988012b77)
- fix(zai): apply the thinking payload patch after the downstream request hooks (d287c94817)

**Upgrade from v2026.11.26-1.** That version fails every agent turn on the pi 1.6 runtime: setting the system prompt throws `Cannot set property systemPrompt of #<Object> which has only a getter`, so chat replies never complete. This release is the first pi 1.6 build that works. The second commit above had no effect at runtime; the third one supersedes it.

## 更新内容

本版本是 `2026.11.26-1` 的修复版，只包含两项修复，没有新功能，也没有配置变更。

### 修复：pi 1.6 下每轮对话失败（3b790232bc）

- `2026.11.26-1` 迁移到 pi-ai 1.6 之后，嵌入式 agent 每一轮在设置系统提示时都会抛出 `Cannot set property systemPrompt of #<Object> which has only a getter`——pi 1.6 的系统提示改为读取时派生，运行时同样是只读的。**`2026.11.26-1` 的 npm 包带有这个问题，聊天回复无法完成**，升级到本版本即可
- 修复方式：改用 pi 1.6 的 `forceSystemPrompt` 选项整体替换系统提示（会话的基础选项和单轮选项都设置）；同时给上下文规范化补上对缺失消息的防护
- 这个问题在部署冒烟时才暴露：live 套件直接调用 `generateText`，不经过这一层

### 修复：`/think off` 在 glm-5.3 上返回 400（d287c94817）

- glm-5.3 系列不能关闭思考。会话档位设为 `off` 时，请求里仍然带着 `thinking: disabled` 发出，接口返回 400（"This model always engages in thinking and cannot be disabled"），这一轮对话失败
- 修复方式：zai 的请求包装器改为在下游请求钩子全部跑完之后，对最终发出的请求做最后一步改写，`off` 改为最低强度 `reasoning_effort: low`
- 在 glm-5.3 上，`off` 的含义是"以最低强度思考"，不是不思考；其余档位的行为不变（minimal / low → low，medium → high，xhigh → max）

### 验证

- 系统提示修复：通过网关的真实对话冒烟正常回复，没有触发回退
- 思考档位：通过运行中的网关在 glm-5.3-flash 上逐档验证，off ×3、minimal、low、medium、xhigh、high 全部成功，请求体携带对应的 `reasoning_effort`；修复前 off 为 6 次全部失败
- 单测：zai 扩展 26/26（新增 5 个用例覆盖"下游钩子重建或恢复 thinking"的场景）、attempt 83/83、system-prompt 6/6
- CI：Install / Test / Check 全部通过
