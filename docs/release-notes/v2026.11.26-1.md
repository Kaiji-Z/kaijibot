## 更新内容

### 依赖升级（pi 系列四包 0.79.4 → 1.6.1）

- `@earendil-works/pi-ai`、`pi-coding-agent`、`pi-agent-core`、`pi-tui` 从 0.79.4 升到 1.6.1——这是 2026 年 6 月首次升级后冻结半年来的第一次大版本跨越；`@anthropic-ai/sdk` override 同步提到 0.129.0。依赖树收敛为单一 pi-ai 1.6.1 副本，`pnpm audit` 保持 0
- pi 1.6 是破坏性大版本：本仓库全部迁移面已完成并通过 `pnpm check`（tsgo / oxlint / 边界检查）、完整 CI 门禁（plugin-sdk exports / api baseline / docs / schema / import-cycles）与构建验证（pi-ai 保持外置，不进 dist）

### 迁移要点

- 兼容层入口从 pi-ai 根导出移到 `@earendil-works/pi-ai/compat`（streamSimple / completeSimple / complete / getEnvApiKey / provider 注册表等）；`clearApiProviders` 更名 `resetApiProviders`
- 会话上下文品牌化：`TranscriptContext` 只能由 pi 产生，系统提示改为以首条 system 消息承载；全部传输层（openai-ws / openai-completions / anthropic / google / ollama）改为从消息流提取系统提示与工具清单，缓存边界剥离同步跟随
- `agent.streamFn` 更名 `agent.streamFunction`；会话默认流判定改用显式 `sessionDefault` 标记（1.6 的基座流不再是 streamSimple）
- 模型注册表/认证改由 `ModelRuntime` 驱动（auth.json + models.json）；同步解析路径使用本仓库的结构化 models.json 回退注册表；pi 1.6 移除 OAuth 公共 API——OpenAI Codex OAuth 登录现明确报"不可用"错误而不是静默失败
- pi-tui 的 `TUI` 类不再是导出值：CLI 界面改用 `TuiMainScreen`；组件 `render` 返回只读行数组
- 思考档位：pi 1.6 新增 `xhigh` 并保留 `max`——对外档位集合去掉 `max`（归一到 high/xhigh），Google 传输的 thinking budget 与 Anthropic 的档位钳制同步映射；Google 的 toolChoice 收窄为 auto/none（强制指定函数的选择不再可达，映射为 AUTO）

- live 重验（真实 LLM + 真实搜索，全部通过）：技能质量门 3/3（refine 路径 0.91 分）、洞察套件 4/4、演化 quality 5/5、演化 e2e 19/19
- plugin-sdk API 基线按流程重生成（provider 钩子上下文的 registry 字段加宽为结构化类型，只提交 `.sha256`）
