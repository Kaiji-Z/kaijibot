# v2026.11.28 Release Notes

## What's Changed

- fix(agents): prepare background models at the direct-compat call sites (8db7d667a9)
- feat(minimax): portal OAuth token refresh, ported from OpenClaw 9e28ade681 (7825877290)
- fix(auth): restore per-provider OAuth refresh via pi-ai provider flows (a568d75c58)
- test(pi): point dead pi-ai mocks at the compat entry (e7027bd670)
- fix(auth-profiles): stop rewriting auth-profiles.json on usage-only saves (25afb29c80)

**Upgrade from v2026.11.27.** This release continues cleaning up regressions from the pi-ai 1.6 migration: expired OAuth profiles stopped refreshing (every provider except chutes), and five background single-turn features (/btw, PDF extraction fallback, generic image description, conversation labels, TTS text summary) failed with HTTP 400 on always-thinking GLM-5.3 models. Both are fixed here. No configuration changes.

## 更新内容

本版本继续清理 pi-ai 1.6 迁移留下的问题：恢复 OAuth 令牌刷新，修复五个后台功能在 glm-5.3 上的 400，另含一项每轮对话提速修复和一次 MiniMax 刷新功能移植。无配置变更。

### 修复：/btw 等五个后台功能在 glm-5.3 上返回 400（8db7d667a9）

- glm-5.3 不能关闭思考，但 `/btw` 侧问、PDF 抽取兜底、通用图片描述、会话标题、TTS 文本摘要这五个调用点把未经准备的模型直接交给请求层，请求里带着 `thinking: disabled` 发出，接口返回 400，功能静默失败
- 修复：五个调用点统一经过 `forBackgroundCompletion` 准备模型（`reasoning_effort: "low"` + `max_completion_tokens`），并处理 pi 1.6 注册表把 `off` 档位填成 null 的情况（回退到模型点名的最低档位；`max_completion_tokens` 不把推理算进额度）
- 范围说明：会话摘要、画像提取、洞察生成、记忆整合等其余后台调用不受此问题影响（它们走的解析路线不受影响），此前"所有后台调用都坏了"的说法不准确
- 验证：真实生产模型（zai/glm-5.3-flash）进程内探针，修复前 `/btw` 抛 400、会话标题返回 null，修复后正常回答、标题正常生成，请求体携带 `reasoning_effort: "low"` + `max_completion_tokens` 且无 `thinking`

### 修复：OAuth 令牌刷新在 pi 1.6 迁移中丢失（a568d75c58）

- pi 1.6 迁移删掉了 `getOAuthApiKey`，此后除 chutes 外所有 provider 的 OAuth 档位过期后不再自动刷新，刷新锁会一直保留旧档位
- 修复：核心在插件刷新之后增加回退——直接调用 pi-ai 内置的各 provider OAuth flow（anthropic、github-copilot、kimi-coding、openai、openai-codex、openrouter、xai 等）；Codex 扩展恢复真实的令牌刷新与受管写回；Google Gemini CLI 扩展恢复 refresh_token 刷新
- 本版本未恢复：Claude CLI 导入的档位、Codex 交互式登录（后续单独处理）

### 新增：MiniMax 开放平台 OAuth 刷新（7825877290）

- KaijiBot 的 MiniMax 扩展此前从未注册过刷新逻辑（onboarding 文案声称"自动刷新"与事实不符）；本次从 OpenClaw `9e28ade681` 移植
- 端点迁移到 account.minimax.io / account.minimaxi.com，登录时记录账号区域（tokenEndpoint），刷新凭区域路由
- 限制：未用真实 MiniMax 账号端到端验证（wire 探测返回 `unauthorized_client`，无法区分是授权未开通还是措辞差异）

### 修复：用量保存不再重写 auth-profiles.json（25afb29c80）

- 用量记账每次保存都改写 auth-profiles.json，mtime 变化使模型目录指纹失效，每轮对话都要重新规划 models.json，稳态单轮 ~25 秒
- 修复后稳态单轮 ~3 秒（已在生产网关部署验证）；重启后首轮 ~20 秒的问题仍存在（models-dev 刷新），后续单独处理

### 测试：pi-ai 死 mock 指向 compat 入口（e7027bd670）

- pi 1.6 迁移后 4 个测试文件的 `vi.mock("@earendil-works/pi-ai")` 整体 mock 失效（源码改从 `/compat` 导入），改为部分 mock，恢复 CI 盲区覆盖
